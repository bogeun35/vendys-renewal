01 / 문제와 목표

홍보의 다음 단계는
“우리 회사도 도입할 수 있을까?”입니다.

식권대장에 대한 사전 인지도가 있다는 기획 전제 아래, 담당자도 자신이 운영하는 회사에 적용할 수 있는지는 별도로 판단해야 합니다. 서비스의 규모나 종류를 나열하는 것만으로는 예산·근무지·정책·정산에 대한 질문이 해결되지 않습니다.

해결할 탐색 문제

  • 우리 회사의 현재 불편과 서비스 기능이 연결되지 않음
  • 임직원 편의와 담당자 운영 근거가 흩어져 있음
  • 내부 결재에 필요한 조건과 미확인 사항을 정리하기 어려움

리뉴얼 목표

  • 문제 중심으로 적합한 서비스를 찾기
  • 공식 화면·사례로 운영 방식을 이해하기
  • 소개서·검토 가이드·계산기에서 상담으로 이어지기
핵심 제안

“좋아 보이는 복지”를 넘어, 담당자가 설명하고 제안할 수 있는 복지.

이 문서는 공개 자료 기반의 디자인 전략입니다. 고객 인터뷰로 검증된 우선순위나 실제 전환 성과를 주장하지 않습니다.

근거와 가설의 구분

공개 근거 식권대장 공식 페이지는 예산·인원·근무환경, 정책 설정과 정산 관리를 안내합니다. 복지대장은 직원 선호·추가 비용·운영 효율을 담당자의 고민으로 제시합니다.

디자인 가설 이 질문을 서비스 목록보다 먼저 다루면 적합성을 판단하기 쉬워질 것입니다. 내부 결재자료가 상담 진입에 도움이 되는지는 실제 담당자 테스트가 필요합니다.

출처: sikdae.com/sikdae, sikdae.com/welfare. 공개 고객사례는 개별 고객 경험이며 모든 기업의 성과를 보장하지 않습니다.

왜 이 순서인가

첫 화면에서 무엇을 제공하고 누구에게 도움이 되는지 전달합니다.

고민 선택으로 서비스명에 익숙하지 않은 담당자도 접근할 수 있게 합니다.

실제 화면과 사례로 주장에 근거를 붙입니다.

검토 자료를 통해 즉시 상담하지 않는 방문자도 다음 행동을 할 수 있게 합니다.

와이어프레임은 구조 설명용입니다. 최종 이미지·비율은 실제 시안에서 확인합니다.

모션의 역할

스크롤에 따라 직원의 이용 장면을 전환하고, 관련 정보가 나타나는 순서를 안내합니다. 버튼 반응은 선택의 결과를 알려줍니다.

현재 구현: 스크롤 연동 앱 이동, 하루 장면 전환, 섹션 등장, 선택 패널 전환.

사용자 제어

자동으로 계속 움직이는 효과를 줄이고, OS 모션 감소 설정과 일시정지를 제공합니다. 애니메이션 없이도 내용을 읽을 수 있어야 합니다.

자연스러운 기본 스크롤 유지. 모션은 정보·접근성을 가리지 않는 범위에서 적용합니다.

항목시안 기준

블로그공식 스토리·회사소개·서비스자료를 편집한4건. 원제와 출처 표기.

계산기모달 진입 복원. 인원×월식대 예산 계산. 실제 절감산식 미확인이므로 절감액 계산과 구분.
내부 자료기획 참고용. NAS 원본 문서와 비공개 데이터를 공개 시안에 포함하지 않음.

10 / 검증과 발표

“예쁘다”를 넘어
도입 검토를 도왔는지 확인합니다.

자체 UI 검수

정렬축·글자·이미지·모달·메뉴·폼과 내부 링크를 점검합니다. 390 / 760 / 800 / 900 / 1001 / 1024 / 1440 / 2445px를 검수 범위로 둡니다.

실제 수행 결과와 남은 항목은 별도 검수 기록에 남깁니다. 자체 점검은 고객 사용성 검증이 아닙니다.

향후 사용자 검증

기업 담당자에게 “우리 회사에 맞는 운영방식 찾기”, “결재 전 확인할 조건 찾기”, “상담 준비하기” 과제를 제시합니다.

측정 계획: 과제 성공 여부·소요시간·오해한 조건·상담 준비 자신감. 아직 측정한 성과가 아닙니다.

3분 시연 순서

  1. 메인에서 담당자의 고민을 선택합니다.
  2. 관련 서비스의 실제 화면과 정책·사례를 확인합니다.
  3. 검토 가이드와 계산기에서 내부 보고 준비를 보여줍니다.
  4. 소개서·상담의 동일한 디자인 흐름을 보여줍니다.
제안의 차별점

식권대장의 인지도를 출발점으로, 기업 담당자의 도입 판단을 끝점으로 설계했습니다. 공식 서비스 근거와 일관된 디자인을 하나의 구매 여정으로 묶습니다.
